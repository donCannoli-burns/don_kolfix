# don_kolfix

**KoLmafia preference recovery and repair tools.** This repository is a fork of [Skaazi's kolfix](https://github.com/s-k-z/kolfix). It provides commands to re-check game information, repair selected local preferences, and mark limited-use resources as exhausted when KoLmafia's saved state is missing or unreliable.

> **Important:** kolfix changes **KoLmafia preferences**, not your actual Kingdom of Loathing account state. Marking an unlock as owned does not grant it in-game. Some repair commands deliberately replace correct values with conservative or maximized ones. Review the commands before using them, especially in automation.

## Installation

### KoLmafia GCLI (published build)

The intended installation command for **this fork** is:

```text
git checkout https://github.com/donCannoli-burns/don_kolfix.git release
```

The `release` branch is the **compiled distribution**, generated by the repository's GitHub Actions workflow from `main`. **It may not yet exist:** if KoLmafia reports that the branch cannot be found, use the source-build instructions below. The `main` branch contains TypeScript source rather than ready-to-run compiled scripts.

After installation, use `git update` in KoLmafia to fetch available updates.

### Build from source (developers / no release branch)

Requires Node.js and Yarn, plus a local KoLmafia installation for the install step.

```bash
git clone https://github.com/donCannoli-burns/don_kolfix.git
cd don_kolfix
yarn install
yarn build
yarn install-mafia
```

**Repeat installation:** `yarn install-mafia` now checks the standard `~/.kolmafia/scripts/kolfix` path. If it is already a symlink resolving to this checkout's `dist/scripts/kolfix`, the installer prints an *already linked* message and exits successfully. If the existing entry is a different symlink, directory, file, or broken link, it refuses to replace it. No installed content is removed. Run `node tools/install-mafia.mjs --check` to inspect link status without trying to install.

```bash
ls -ld ~/.kolmafia/scripts/kolfix
readlink -f ~/.kolmafia/scripts/kolfix
readlink -f ~/repos/donCannoli-burns/don_kolfix/dist/scripts/kolfix
```

If the real paths match, a successful `yarn build` already refreshes the code through the existing link, so reinstalling is unnecessary. Do not delete the existing entry until verifying whether it is a user-maintained directory or a symlink owned by another installation.

The build task outputs `dist/scripts/kolfix/kolfix.js`. The `install-mafia` task uses the repository's `create-kolmafia-script --install` integration; configure your local KoLmafia installation if that tool requests it. For source changes, `yarn watch` rebuilds on edits and `yarn lint` checks code style.

## Quick start

Run this in the KoLmafia Graphical CLI (GCLI) to see the script's built-in help:

```text
kolfix
```

Examples:

```text
kolfix auto
kolfix cleaver
kolfix maximizer
kolfix recommend
kolfix numberology=3 pool=10
kolfix mall=100000 voa=5000
```

Options can be combined. For example, `kolfix auto maxAll` checks recoverable game data **and** applies the explicit maximum/unlock settings described below; `maxAll` by itself does not run `auto`.

## Commands

### Inspect and recover information

| Option | Action |
| --- | --- |
| `auto` | Visits relevant KoL pages and descriptions to refresh inferable information: quest and location state, crafting discoveries (including Cookbookbat recipes), locket state when fully used, Cincho de Mayo, designer sweatpants, Powerful Glove, getaway campsite, parts of Gingerbread City, Puzzle Champ, Source Terminal, and Spacegate vaccination details. Some values cannot be inferred after their daily resource is used. |
| `session` | Reads the latest session log and replays recorded `Preference ... changed from ... to ...` values into KoLmafia preferences. **Potentially broad overwrite; back up preferences and inspect the result.** |
| `recommend` | Prints a manual checklist for settings such as combat behavior and automatic item sourcing. Does not apply the recommendations. |

### Repair or exhaust limited-use resources

| Option | Action |
| --- | --- |
| `cleaver` | Sets June Cleaver encounter/skip/fight counters to conservative automation-friendly values for the day. |
| `disableCombatSkills` | Marks the script's supported limited-use combat skills, banishes, and runaways as expended. |
| `disableLocket` | Sets `_locketMonstersFought` to `0,0,0`. This is a fallback, **not** a reconstruction of which monsters were fought. |
| `disableSausageGoblin` | Pushes `_lastSausageMonsterTurn` far into the future so automation does not expect a Kramco sausage goblin. |
| `disableShotglass` | Marks the Mime Army Shotglass as used. |
| `disableLegendaryPizzas` | Marks the three legendary Cookbookbat pizzas as eaten for the current lifetime. |
| `disableShockingLick` | Sets `shockingLickCharges` to zero; later battery use can change the actual value. |
| `disableAll` | Applies `cleaver` and all of the `disable...` options above. **This is a broad fallback, not a state-recovery scan.** |

These are local preference edits. Daily flags generally reset at rollover or ascension; lifetime flags generally persist until ascension. Actual behavior depends on KoLmafia and the relevant game mechanic.

### Set values and toggle options

| Option | Action |
| --- | --- |
| `numberology=N` | Sets the Manual of Numberology count (intended maximum: 5). |
| `pool=N` | Sets Rack 'em Up count for permanent pool skill (intended maximum: 25). |
| `glitch=N` | Sets `glitchItemImplementationCount`. |
| `max` | Defaults Numberology to 5 and pool count to 25, unless numeric overrides are provided. |
| `maxAll` | Includes `max` and marks Gingerbread City (with wall thickening), Tunnel of L.O.V.E., and LT&T Office as permanently available in KoLmafia's preferences. |
| `gingerbread` | Toggles Gingerbread City availability **and** wall thickening. |
| `love` | Toggles Tunnel of L.O.V.E. availability. |
| `ltt` | Toggles LT&T Office availability. |
| `mall=N` | Sets `autoBuyPriceLimit`. Values above 250,000 are warned about, **not blocked**. |
| `voa=N` | Sets `valueOfAdventure`. Values above 10,000 are warned about, **not blocked**. |
| `yetiCold` | Sets `choiceAdventure1560 = 2`, selecting the Cooler Yeti’s **“Make my next drink impossibly cold!”** option when available. Also applied by `auto`. |
| `maximizer` | Resets `maximizerMRUList` to KoLmafia's default; restart KoLmafia afterward. |
| `popups` | Toggles `suppressNegativeStatusPopup`, which controls certain negative-status mini-browser popups. |

**Toggle warning:** Running `gingerbread`, `love`, `ltt` or `popups` a second time reverses the setting. Use `maxAll` to set the supported permanent-unlock preferences to true rather than toggling them.

### Cooler Yeti drink-cooling choice

```text
kolfix yetiCold
get choiceAdventure1560
```

The configured value should be `2` (choice adventure 1560, **“Make my next drink impossibly cold!”**). `kolfix auto` also applies this preference after any session-log restoration in the same invocation.

**This is a choice preference, not a claim that the drink boost has been used.** KoLmafia determines `_coolerYetiAdventures` (the once-per-day usage flag) and `coolerYetiMode` (expected `adventures` after the choice) from actual game responses. `kolfix` deliberately does not forge these game-state fields, grant familiar XP, or initiate the choice.

## Recovery recipes

### Recover inferable state after preference loss

```text
kolfix auto
```

The `auto` scan refreshes values KoLmafia can learn by visiting pages. It does **not** reconstruct everything: some previously used daily resources and permanent unlocks are not observable from page visits.

### Keep a damaged automation run moving

```text
kolfix disableAll
```

This deliberately tells KoLmafia to behave as though many limited resources have been spent. It can prevent scripts from trying unavailable abilities, but may waste resources that were actually still available. Use only when that tradeoff is acceptable.

### Restore preference changes from a log

```text
kolfix session
```

This replays preference-change entries from the most recent session log. **It is not a selective rollback:** it can overwrite current settings, including settings unrelated to the immediate failure. Make a backup of your KoLmafia preferences first, and verify key values afterward.

### Repair maximizer recent-history problems

```text
kolfix maximizer
```

Restart KoLmafia after running this command.

### Set known permanent values

```text
kolfix numberology=3 pool=10
kolfix auto maxAll
```

Use `maxAll` only if the associated unlocks and upgrades are actually owned in-game.

### Calculate glitch item implementations

The `glitch` value can be derived from a recent `%monster%` meat drop when you know how many `[glitch season reward name]` items you own:

```text
implementations = monster_meat_drop / (5 * glitch_items_owned)
```

For a drop of 1,000 Meat and two items, the value is 100:

```text
kolfix glitch=100
```

## Don State Engine v0.2 — preferences (explicit opt-in)

This fork also defines a **namespaced and typed preference contract** for the observation/journal design being developed in [don_custom_functions](https://github.com/donCannoli-burns/don_custom_functions/pull/5). The new options are available in `main` source; once the compiled `release` branch has been rebuilt, the KoLmafia CLI can use:

```text
kolfix stateStatus     # inspect cached policy/flags, no preference changes
kolfix stateInit       # initialize missing defaults; no rollover/ascension reset
kolfix stateVerify     # validate current values, no automatic repair
```

`stateInit` writes only **missing, non-empty defaults** and never overwrites an existing non-empty value. It does not add hooks, start the State Engine, launch adventure scripts, change the gameplay account, or mark workflow phases as completed. All three state commands exit before legacy `auto`, `disableAll`, `session`, and other repair operations; don't mix them with unrelated options on the same invocation.

### Preference contract

| KoLmafia preference | Initial value | Meaning |
| --- | --- | --- |
| `donState_schemaVersion` | `0.2` | Versioned schema |
| `donState_loopRun` | `false` | Intended looping mode, not execution permission |
| `donState_stopForDiscrepancy` | `true` | Fail closed on inconsistent evidence |
| `donState_autoFallback` / `donState_nextFallback` | `false` | Safe fallback policy and queued fallback |
| `donState_maxAutomaticAdventureSpend` | `0` | Default is no automatically budgeted turns |
| `donState_nextFlagExpected` / `donState_nextFallbackFlag` | unset | Named workflow IDs, not CLI commands |
| `donState_scopePlayerId`, `donState_scopeDay`, `donState_scopeAscensions` | unset | Future journal-attested player/day/life scope |
| `donState_lastProjectionReceipt` | unset | Journal evidence link; not self-authenticating |
| `donState_lastFlagName`, `donState_lastFlagActivation`, `donState_lastFlagEdit` | unset | Last journal-derived phase/timestamps |
| `donState_flag_<phase>` | `0` | One per 26 canonical phase/substate names |
| `donState_discrepancy_1..5` and `donState_discrepancy_N_note` | `false` / unset | Dashboard projection of first five issues |
| `donState_nextHalloween`, `donState_daysTillHalloween` | unset / `unknown` | Calendar evidence not yet connected |
| `donState_isHalloween`, `donState_eveOfHalloween`, `donState_eveOfEvent`, `donState_eventEvidence` | `unknown` | No invented holiday result |

Phase code legend: `0=pending`, `1=started`, `2=finished`, `3=skipped`, `4=failed`, `5=needs_reconciliation`.

The phase names are the exact `DON_STATE_FLAGS` list in [src/state-preferences.ts](src/state-preferences.ts), including `start_day`, `setup_l1`, `leg1_farm`, `post_farm_l1`, `ascension`, `post_ascension_hook`, `path_run`, `new_life`, `leg2_farm`, `end_day`, and supporting resource/organ/ronin/market flags.

**Important distinction:** KoLmafia preferences can be edited manually or by scripts; they are **not** proof that any turn was spent, an item obtained, or an ascension completed. The append-only journal remains the source of evidence. `stateInit` deliberately leaves scope identifiers unset; another validated observer/journal component must bind them before cached nonzero flag statuses are trusted. It never auto-resets flags at rollover or ascension. The broad `kolfix session` recovery command explicitly skips `donState_` entries so historic logs cannot replay stale phase statuses across a new life.

### Verification

Before using a local source build, run `yarn lint`, `yarn build`, and `npx tsc --noEmit`. After compiling/installing the release, `kolfix stateStatus` should make no changes. Use `kolfix stateInit` only when you intentionally want missing defaults created. Verify that rerunning `stateInit` leaves existing non-empty flags unchanged. No live gameplay is needed for these checks.

## Safety and troubleshooting

- **Back up your KoLmafia preference files** before broad recovery commands, especially `session`, `disableAll`, and `maxAll`.
- Use `kolfix` to inspect available options; start with a targeted repair rather than assuming every setting needs to be reset.
- If an item, effect, or property is not recognized, update KoLmafia. Some supported mechanics require newer KoLmafia data.
- A command reporting completion does not independently prove the game account owns an unlock or that every preference is correct. Inspect relevant values using KoLmafia's `prefref` or `get`/`set` tools.
- If the `release` branch is unavailable, do **not** substitute `main` as a compiled-script installation. Build the source or publish the distribution first.

## Settings backup, verification, restore, rollback and GCLI status

The Linux host companion `tools/kolfix-settings` safely archives the **actual**
KoLmafia `settings/` files, including byte-exact `GLOBAL_aliases.txt`, and
stages or restores them to a separate KoLmafia installation. Archives are
verified with SHA-256; restore requires explicit confirmation that KoLmafia is
stopped, and Docker-mounted Xpra installs can verify container/mount identity.
A rollback snapshot is preserved before replacement.

Use `kolfix backupStatus` from the gCLI for a **read-only** report of the last
successful host operation, or `call kolfix_backup_status.ash`. For the short
`backup-status` command, register an optional gCLI alias once:
`alias backup-status => call kolfix_backup_status.ash;`

See [docs/settings-backup.md](docs/settings-backup.md) for commands, safety
restrictions, installation locations, legacy snapshot support, and recovery.
The GCLI viewer never accesses Docker or mutates preferences. Only the host
program can create/restore settings archives. **Never commit settings backups.**
